# Unit Test Evidence Boundary Review

Use when unit tests and results already exist. From supplied sanitized excerpts, record behavior claim, test case, assertion, fixture or mock boundary, observed result, missing branch, false-confidence risk, scope, and unknown. Distinguish evidence about one unit from integration, reliability, security, or production claims it cannot support.

Return a private boundary review and proposed human-run checks marked `NOT RUN`. Do not access repositories or files, run tests, generate test code, change fixtures or implementation, approve completion, create tickets, send, or publish.
